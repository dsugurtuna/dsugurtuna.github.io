Systems & Reference Architectures

Practical architecture, control, evaluation, and assurance systems in code.

Every public repository pairs runnable Python or multi-service code with architectural decision records (docs/WHY.md / ADRs), automated offline CI tests, and explicit labels distinguishing deterministic libraries, synthetic benchmarks, mocked boundaries, and design-level infrastructure.

Core AI systems

Four connected open-source architectures built to test how AI systems scale safely and economically.

  • 01 · Architect & price

    ai-systems-architecture

    Reference architecture · Synthetic benchmarks · Offline CLI

    Which deployment boundary fits your residency rules, and when do frontier endpoints or self-hosted open-weights win on total cost?

    Deterministic architecture validator (13 residency, zero-data-retention, capability, failover parity, latency, and security gates), tiered routing TCO simulator across frontier and open-weights regimes, and ADRs.

    • AI architecture
    • Model routing
    • TCO economics
    • Synthetic data

  • 02 · Control execution

    agent-guardrails

    Tested Python library · Offline runtime guard

    How do you let an AI agent act without it sending the wrong thing, twice, to the wrong people?

    Runtime control layer for AI agents that write or send: allow/draft/approve/block modes, execution-time TOCTOU re-validation, normalised idempotency, SHA-256 hash-chained audit logs, kill switch, and OpenAI, Azure OpenAI, and Anthropic Claude tool-loop adapters.

    • Agentic AI
    • Tool-use guardrails
    • OpenAI / Azure / Claude
    • Audit log
    • OWASP LLM

  • 03 · Verify quality

    evidence-synthesis-eval

    UK AISI Inspect plugin · Synthetic dataset

    Does an AI synthesis say what the sources say, what did it miss, and what did verification cost?

    Open evaluation harness built on UK AISI Inspect for retrieval-grounded (RAG) and synthesis workflows: faithfulness, importance-weighted coverage, misstatement rates, blinded human-judge agreement (Cohen’s kappa), and checking effort.

    • LLM evaluation
    • Inspect AI
    • Benchmarking
    • Faithfulness

  • 04 · Govern & assure

    ai-assurance-kit

    Open-source kit · Public templates · Illustrative mappings

    How can a team run proportionate AI assurance in an afternoon rather than a quarter?

    Open-source policy-as-code kit turning AI use cases into schema-validated YAML records, 26 explainable reviewer checks, executive one-page cards, three unofficial template adaptations of public GOV.UK ATRS records, and UK Government AI Playbook / NIST AI RMF mappings (with non-normative orientation tables — not legal advice or compliance certification).

    • Policy-as-code
    • AI Assurance
    • GOV.UK ATRS
    • NIST AI RMF

Engineering discipline

  • Tested open-source packages with automated offline CI test suites and architectural decision notes (docs/WHY.md / ADRs).
  • Honest operational boundaries: every README separates deterministic Python checks from synthetic inputs, mocked model boundaries, and design-level infrastructure (Kubernetes (design), Terraform (design)).
